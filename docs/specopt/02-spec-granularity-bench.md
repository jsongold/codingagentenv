# SpecOpt：Spec の粒度とトークン消費の実測（途中報告）

目的：CA に渡す Spec の粒度（x1 / x5 / x10）で、トークン消費と合否がどう変わるかを、品質の高い OSS の実コミットで測った結果を残す。計画した 3 回の反復のうち、1 回目の途中までの報告。

- 実施日：2026-10-12。親：Epic CAO-2、Story CAO-4。前提の調査は `01-web-research.md`
- 状態：1 回目の test は 29 件中 15 件まで。2 回目・3 回目は未実施（利用枠の上限で中断）

## 1. 方法

| 項目 | 内容 |
|---|---|
| ケース | OSS の実コミット。実コミットではテストが通り、親コミットに同じテストを置くと落ちることを確認したもの |
| 合否 | 実コミットのテスト。テストは最初から作業ツリーに置き、全粒度で同じ受入コマンドを渡す |
| 隔離 | 親コミットの中身だけを取り出した履歴なしの作業ツリー。実コミットは見えない |
| CA | Claude Code 2.1.296 のヘッドレス実行、モデルは sonnet。ユーザー設定・skill・MCP なし |
| 権限 | Bash サンドボックスを有効にし、その中の Bash は全部許可（書き込みは作業ツリーとキャッシュだけ） |
| Spec | opencode が実コミットの差分から英語で作成。末尾の受入の節は機械的に同じものを付ける |
| 回数 | 1 ケース × 1 粒度につき 2 回。集計はケースごとの平均で行う |

Spec の粒度

| 粒度 | 中身 | 語数（中央値、受入の節を含む） |
|---|---|---|
| x1 | 目的だけ（1〜2 文） | 97 |
| x5 | 目的、触るファイル、決定済みの変更、制約 | 230 |
| x10 | x5 に加えて、関数単位の場所、順番つきの手順、従う既存パターン | 437 |

ケースの出どころ（検査に通った数 / 候補）

| repo | 言語 | stars | 検査 | 実行済み |
|---|---|---|---|---|
| go-chi/chi | Go | 22,949 | 11 / 15 | 0（選定 4） |
| spf13/cobra | Go | 44,697 | 11 / 15 | 0（選定 4） |
| pelletier/go-toml | Go | 1,991 | 15 / 15 | 0（選定 4） |
| stretchr/testify | Go | 26,224 | 10 / 15 | 4 |
| pallets/click | Python | 17,789 | 13 / 15 | 3（選定 5） |
| pallets/jinja | Python | 11,795 | 12 / 15 | 4 |
| unjs/ufo | TypeScript | 1,303 | 12 / 15 | 4 |
| tj/commander.js | JavaScript | 28,412 | 0 / 15 | 対象外（テストの仕組みが途中で変わっている） |

選定した 29 件は、大きさ（ソースの変更 3〜133 行）、種類（機能追加・修正・リファクタ・非推奨化・セキュリティ修正）、触るファイル数（1〜5）が散らばるように選んだ。

## 2. 結果（15 件 × 3 粒度 × 2 回 = 90 回）

| 粒度 | 合格率 | 総トークン（中央値） | 出力トークン（中央値） | ターン数（中央値） | 時間（中央値） |
|---|---|---|---|---|---|
| x1 | 96.7% | 68,425 | 1,521 | 5.5 | 22.2 秒 |
| x5 | 93.3% | 63,234 | 1,480 | 5.0 | 17.1 秒 |
| x10 | 93.3% | 42,645 | 1,187 | 4.0 | 13.0 秒 |

同じケースどうしの比（中央値と 95% 信頼区間）

| 比 | 総トークン | ターン数 | 小さくなったケースの割合（総トークン） |
|---|---|---|---|
| x5 ÷ x1 | 0.86 [0.65, 1.02] | 0.89 [0.71, 1.27] | 66.7% |
| x10 ÷ x1 | 0.73 [0.56, 0.75] | 0.80 [0.64, 1.00] | 93.3% |
| x10 ÷ x5 | 0.84 [0.73, 1.03] | 0.92 [0.73, 1.00] | 60.0% |

言えること
- x10 は x1 より総トークンが約 27% 少ない。15 件中 14 件で減り、信頼区間は 1 をまたがない。
- x5 は x1 より少ない傾向だが、信頼区間が 1 をまたぐ。15 件では差があるとは言えない。
- 実行ごとのばらつき（同じ条件 2 回の最大 ÷ 最小の中央値）は、x1 が 1.39、x5 が 1.13、x10 が 1.07。Spec が細かいほど結果が安定する。
- 合格率は粒度でほとんど変わらない。テストを最初から渡す条件では、品質の差は出なかった。

言えないこと
- 各粒度に、エラー終了の実行が 3 回、不合格が 1〜2 回ある。原因は未確認（利用枠の上限に達した時刻と重なっている可能性がある）。
- Go は 4 件（testify だけ）、TypeScript は 4 件で、言語別の差は読めない。
- Spec を書くコストは測っていない。x10 の Spec は実コミットの差分から作っており、実運用で同じ細かさの Spec を作れるかは別の問い。

## 3. 何にターンを使っているか（参考）

権限の設定を直す前のデータ（71 回、全部合格）を transcript から数えたもの。権限の拒否が混ざっているので、傾向だけを見る。

| 項目（中央値） | x1 | x5 | x10 |
|---|---|---|---|
| 最初の編集までのツール呼び出し | 4 | 3 | 1 |
| テストの実行回数 | 2 | 2 | 2 |
| テスト実行後の手直し | 1 | 0.5 | 0 |
| 終わりの報告の長さ | 518 字 | 463 字 | 544 字 |

- 総トークンはターン数にほぼ比例する（相関係数 0.88）。毎ターン読み直される固定分が支配している。
- 粒度で減るのは、編集に入るまでの探索と、テスト後の手直し。
- 粒度で変わらないのは、テストを 2 回実行することと、終わりに約 500 字の報告を書くこと。

## 4. 再調査で確かめたこと（OSS と研究）

原文で裏取りしたものだけを書く。

| 事実 | 条件 | 出どころ |
|---|---|---|
| 編集箇所を最初に与えると、1 件あたりのコストが下がる（baseline $2.18、編集箇所だけで $0.84。後者は図からの読み取り） | SWE-agent、GPT-4o、SWE-bench Verified | [arXiv 2604.07789](https://arxiv.org/abs/2604.07789) |
| 場所の context はファイル単位が最も効き、行単位まで広げると性能が下がることが多い | GPT-5-mini、SWE-bench Verified 500 件、61 構成 | [arXiv 2604.05481](https://arxiv.org/abs/2604.05481) |
| ファイルの骨組みを使った場所の特定は、全文より安く（$0.02 対 $0.15）、正解位置を含む率も高い（58.33% 対 53.67%） | Agentless、GPT-4o、SWE-bench Lite | [arXiv 2407.01489](https://arxiv.org/abs/2407.01489) |
| 「テストはもう用意してある。テストを変える必要はない」と最初に伝えている | SWE-agent の既定のテンプレート | [config/default.yaml](https://raw.githubusercontent.com/SWE-agent/SWE-agent/main/config/default.yaml) |
| 「複数の操作は 1 回にまとめよ」「探索は、変える箇所を名指しできたら止めよ」と指示している | OpenHands、OpenAI の Codex / GPT-5 のガイド | [Codex guide](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide)、[GPT-5 guide](https://cookbook.openai.com/examples/gpt-5/gpt-5_prompting_guide) |
| 「計画に書くのは、決めたこと（どのファイル、どの名前と署名）だけ。コードより長い計画は、コードを書いてしまっている」 | superpowers の writing-plans | [SKILL.md](https://raw.githubusercontent.com/obra/superpowers/main/skills/writing-plans/SKILL.md) |

見つからなかったもの
- 「テストは 1 回だけ実行」「終わりの報告を短く」「まとめて呼ぶ」といった指示が、コーディング agent のターンやトークンを減らすことを測った公開の実測（並列呼び出しの実測は Web 調査のタスクのもの）
- Spec の語数を変えて、コーディング agent のトークンとターンを比べた公開の実測

## 5. 途中で直したこと

- 最初の 90 回は、68 回で CA のコマンドが権限で拒否されていた（Python スクリプトでの書き換え、相対パスやパイプつきのテスト実行）。拒否はやり直しのターンを生み、細かい Spec ほど不利に出るので、この分は数字に使っていない。
- Bash サンドボックスを有効にし、その中の Bash を全部許可して取り直した。取り直した 90 回では拒否は 0 件。
- サンドボックスを有効にすると、1 ターンあたりの固定分が約 7.7K から約 12K トークンに増える。全粒度に同じだけ乗る。
