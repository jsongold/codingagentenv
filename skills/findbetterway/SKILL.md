# findbetterway — 使う前に、もっと良い手段を探す

目的：候補を採用して検証・実装に入る前に、同じ問題を解くより良い手段が無いかを確かめる。候補名ではなく問題で探す。

1. 解きたい問題を1行で書く。候補ツールの名前ではなく、「何が困っているか」で書く。
2. 手段を棚卸しする。こちらの候補だけで範囲を狭めない。次の観点を漏れなく見る。
   - すでに環境にあるもの（Claude Code 本体・設定・hooks・built-in の機能、すでに入っているツール）
   - 主要プレイヤーの公式機能・サービス（Anthropic / OpenAI / Google / GitHub / クラウドベンダの SDK・公式 MCP・公式プラグイン）
   - OSS（star が少なくても保守が活発なものを含む）
   - 作らない・入れない選択（現状維持）
3. 調査は Subagent ではなく opencode に出す。`opencode run "<prompt>" < /dev/null`（`< /dev/null` が無いと stdin 待ちで止まる。並列実行は不可）。prompt には次を必ず入れる。
   - 棚卸しが先であること、現在の候補も比較対象に含めること
   - 各手段の保守主体と最終リリース / 最終コミット日、根拠の URL（原文）
   - 確認できないことは「未確認」と書くこと
4. main が、推奨に挙がった上位候補を公式 docs・リポジトリの原文で確かめる。opencode の出力は誤ることがある。記憶から製品名・フラグ・仕様を断言しない。
5. 概要レベルで報告する：手段の名前・1行説明・保守主体・推奨順。詳細は聞かれたとき、または話が次の段階に進んだときだけ書く。結論が「現状の候補のまま」でもよい。報告は選択肢で終える。
