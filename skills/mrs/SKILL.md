# mrs — minimum req spec を書く

責任は「何ができれば OK か」を最小の形で書くところまで。設計・Task 分割・登録は扱わない。

## 手順
1. 入力を読む。Jira Key / Issue 番号なら本文を取得する。
2. 次の 5 項目だけで書く。20 行を目安にし、超えるなら削る。
   - 目的：1〜2 行。冒頭に `目的：` の行を置く
   - OK の定義：実物 1 件で確認できる形で書く（例：小さな実チケット 1 件で、A → B → C が最後まで通る）
   - 守ること：破ると困るものだけ。最大 3 つ
   - NG のとき：止めて報告するだけにできるなら、そう書く（リトライや修正ループは入れない）
   - 今回やらないもの：元の依頼にあるが今回は作らないもの。1 行ずつ
3. 「OK の定義」が決められないときだけ、ユーザーに聞く。それ以外は聞かずに書く。
4. 書いた spec を見せて終わる。承認を得るまで登録・実装・Task 分割に進まない。

## 書き方の基準
- 迷ったら削る。「あると良い」は 今回やらないものへ回す
- 「OK の定義」が 1 つの実行例で確認できないなら、まだ大きい。小さくする
- 実装方式・技術選定は書かない（`/design` の仕事）

## やらないこと
- 設計（`/design`）、Task への分割（`/changegraph`）、チケットや Story の登録（main loop の仕事）
