# prtestdesc

PR 本文の次の 3 節を書く。既存の PR では、既存の書式に合わせて追記する。

## 書式

````
## できること
- [ ] C<n>: <〜できる>

## テスト結果
| TC | 要件 | OK の状態 | 結果 |
|---|---|---|---|
| C<n> | <要件> | <判定に使う出力> | 未実行 |

**証跡**：未実行（実行後に、環境・Commit SHA・日時を記入する）

## 検証手順
### 準備
<worktree 作成〜共通変数の定義>

### C<n> <要件>
OK の状態：<1 行>

<手順が複数あるときは番号を振る。1 手順 = 1 コードブロック>

予期する結果：
```
<判定に使う行だけ>
```

### 片付け
<そのテストで作った物をすべて消す・元に戻すコマンド>
````

## ルール
- 予期する結果は、人が合否を判定するのに使う行だけ書く（例: `exit=10`、`ls -l` の 1 行）。ログ全体は書かない
- 実行ごとに変わる値は `<...>` にする
- コマンドは、コピペでそのまま動く形で直書きする。シェル関数にしない
- 変数（`$WORK` など）は準備で定義する。TC の中で新しく使うものは、その TC の中で定義する
- 設定を変える TC は、元に戻す手順を TC の中と片付けの両方に書く
- 結果の列は、実行結果を見るまで「未実行」にする
- 予期する結果をソースから推測したときは、その旨をユーザーに伝える
- 更新は `gh api -X PATCH repos/{owner}/{repo}/pulls/<N> -F body=@<file>` を使う（`gh pr edit` は Projects classic のエラーで失敗する）
