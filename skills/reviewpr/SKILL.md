# reviewpr — PR レビューのセッションのルールと手順

レビューをどのセッションで行うかのルールは、ここだけに書く。ほかの文書・skill には書かず、ここを参照する。

## ルール
1. PR の初回レビューは、新規セッションか、`/clear` した review 専用セッションで行う。
2. 同じ PR の再レビューは、初回と同じセッションで行う（`/clear` しない）。
3. その PR を実装したセッションと、その文脈を引き継ぐ fork では、レビューしない。

Subagent に出す場合も同じ。初回は新規の Agent に出し（fork は使わない）、再レビューは同じ Agent に続けて頼む。

## 手順
1. 今のセッションがどれに当たるかを判定し、当てはまる行のとおりにする。

   | 今のセッション | すること |
   |---|---|
   | この PR を実装した、またはその文脈を持っている | レビューせずに止める。新規セッションで `/reviewpr <PR 番号>` を実行するよう伝える |
   | 別の PR・別の作業の文脈が残っている | レビューせずに止める。`/clear` してから `/reviewpr <PR 番号>` を実行するよう伝える |
   | 文脈が空（新規、または `/clear` の直後） | 初回レビューとして手順 2 へ |
   | このセッションで同じ PR をすでにレビューしている | 再レビューとして手順 3 へ |

2. 初回レビュー：セッションに `review-pr-<PR 番号>` という名前を付けるようユーザーに頼む（再レビューで同じセッションを探すため）。そのあとレビューする。
3. 再レビュー：前回の指摘が直ったかを先に確認し、そのあと新しい差分を見る。

## やらないこと
- レビューの観点と、指摘の書き方・出力先を決める（project の決まりに従う）
- merge するかどうかの判断
