# Task 仕様 — worker に渡す形と、一緒に渡す context

目的：main が worker に Task を渡すときの仕様の形と、一緒に渡す context・渡さない context の線引きを、この 1 枚で読めるようにする。

## 誰がいつ書くか
main が、配送役を呼ぶ前に、Task ごとに 1 ファイル書く。置き場所は repo にコミットしない場所（session の scratchpad など）。配送役にはパスだけを渡す。worker には `worker-start --spec "$(cat <パス>)"` で本文が渡る。

## ひな形
コピーして埋める。見出しはこの綴りのまま使い、節は 5 つから増やさない。

````markdown
# <チケットの Key>：<Task 名>

目的：<1〜2 行>

## Target
- `<触るファイルのパス>`（新規 | 既存）

## Change
<何をどう変えるか。決定済みの内容を書く。worker に決めさせない>

## Constraints
- <やらないこと。この Task に効くルールだけ>
- <却下済みの案は「〜はしない」の 1 行>

## Ownership
- 編集してよいのは `<パス>` だけ。それ以外は触らない。
- コミットは 1 つ。メッセージ：`<メッセージ>`
- push・PR 作成・merge・チケットの更新：<誰がやるか>
- 終わったら `worker_done` で、<報告の中身> を 10 行以内で報告する。

## Observable acceptance
<実行する場所> で次が <期待する結果> になる。

```sh
<done コマンド。コピペで実行でき、exit code か出力で合否がわかる>
```
````

## context の線引き
原則：worker がその Task を done にするのに要り、repo から自分で読めないものだけを渡す。context 用の節は作らない。渡すものは、上の 5 つの節のどこかに書く。

## 渡すもの
- チケットの Key
- 目的（1〜2 行）
- 触るファイルのパス
- 決定済みの内容（設計の結論）
- この Task に効く制約
- done コマンド
- 報告の形（10 行以内）

## 渡さないもの
- 会話の履歴と handoff の全文
- 検討の経緯と却下案の詳細
- 他の Task の仕様と Task 一覧の全体
- ファイルの本文（パスで渡し、worker が読む）
- CLAUDE.md とハーネスのルールの写し（worker が起動時に自分で読む）
- Orca の guide とコマンド
- token などの秘密情報
