# Task 仕様 — worker に渡す形と、一緒に渡す context

目的：main が worker に Task を渡すときの仕様の形と、一緒に渡す context・渡さない context の線引きを、この 1 枚で読めるようにする。

## 誰がいつ書くか
main が、Task を worker に振ると決めたときに、Task ごとに 1 ファイル書く。置き場所は repo にコミットしない場所（session の scratchpad など）。配送役に任せるときはパスだけを渡す。worker には `worker-start --spec "$(cat <パス>)"` で本文が渡る。

## ひな形
コピーして埋める。見出しはこの綴りのまま使い、節は 5 つから増やさない。

````markdown
# <チケットの Key>：<Task 名>

目的：<1〜2 行>

## Target
- `<触るファイルのパス>`（新規 | 既存）

## Change
<何をどう変えるか。決定済みの内容を書く。worker に決めさせない>

## Constraints
- <やらないこと。この Task に効くルールだけ>
- <却下済みの案は「〜はしない」の 1 行>

## Ownership
- 編集してよいのは `<パス>` だけ。それ以外は触らない。
- コミットは 1 つ。メッセージ：`<メッセージ>`
- push・PR 作成・merge・チケットの更新：<誰がやるか>
- 終わったら `worker_done` で、<報告の中身> を 10 行以内で報告する。

## Observable acceptance
<実行する場所> で次が <期待する結果> になる。

```sh
<done コマンド。コピペで実行でき、exit code か出力で合否がわかる>
```
````

## context の線引き
原則：worker がその Task を done にするのに要り、repo から自分で読めないものだけを渡す。context 用の節は作らない。渡すものは、上の 5 つの節のどこかに書く。

## 渡すもの
- チケットの Key
- 目的（1〜2 行）
- 触るファイルのパス
- 決定済みの内容（設計の結論）
- この Task に効く制約
- done コマンド
- 報告の形（10 行以内）

## 渡さないもの
- 会話の履歴と handoff の全文
- 検討の経緯と却下案の詳細
- 他の Task の仕様と Task 一覧の全体
- ファイルの本文（パスで渡し、worker が読む）
- CLAUDE.md とハーネスのルールの写し（worker が起動時に自分で読む）
- Orca の guide とコマンド
- token などの秘密情報

## 測定にもとづく推奨（CAO-130）

出典：`docs/research/subagent-conditions-results.md`（同じ benchmark Task、1 度に 1 条件、n=1。baseline 3 本の token は 295,537〜683,579 で、この揺れ以内の差は「差とは言えない」）。

- C1（Task の粒度）：現行を維持（1 Task = 1 コミット。Target 数の上限は決めない）。根拠：Target 1 個 300,716 / 6 個 433,347 が baseline の揺れ以内。
- C2（渡す文脈の量）：現行を維持（「渡すもの」の 7 項目だけ）。仕様の行数を減らすこと自体を目的にしない。根拠：20 行 358,935 / 120 行 354,162 が baseline の median 352,938 とほぼ同じ。
- C3（Change の書き方）：番号付き手順は 3 件までにする（暫定）。根拠：6 件が 989,530 で baseline の median の 2.80 倍。揺れを超えた唯一の水準だが n=1 なので追試が要る。
- C4（done コマンドの形）：現行を維持（コピペで実行でき、exit code か出力で合否がわかる）。根拠：grep の連結 347,293 / 複合 290,945 が揺れ以内。
- C5（報告の長さ上限）：現行を維持（10 行以内）。根拠：3 文 415,575 / 上限なし 289,563 が揺れ以内。main 側の token は未測定。
- C6（worker のモデル）：推奨は決めない。worker の既定は haiku（実測）。根拠：sonnet 166,001 / opus 277,709 が揺れ以内で、単価を掛けた費用の比は未算出。変えるときは `orca orchestration worker-start --model <id>`。
- C7（worker に決めさせる範囲）：現行を維持（Change には決定済みの内容を書く）。根拠：目的と制約だけ 349,969 / 候補案つき 354,215 が揺れ以内。done が repo の外のテストなので、設計のずれは測れていない。
- C8（質問の許可）：現行を維持（配送役が答える）。根拠：worker が質問を 1 回もしなかったので、往復の影響は測れていない。「main まで上げる」は未測定。

完了率は全 19 run が初回で通り、差は出ていない。差を言うには、より難しい Task で同条件を複数本回し、main と配送役の token も測る必要がある（未実施）。
