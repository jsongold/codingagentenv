# h5textbook — 学んだ内容を教科書にする

引数は任意（トピックのヒント）。無ければ会話で学んだ内容から決める。

checkpoint は `~/projects/h5notebook/textbooks/<トピック>/.checkpoint`（JSON：`{"sessionId": "...", "uuid": "..."}`）。そのトピックに最後に書き込んだときに読み終えた会話の位置。会話は次で読む（このセッションの transcript から、`<uuid>` より後の user / assistant の本文を出す。省略すると最初から。最後の行が次の checkpoint）。

```
node ${CLAUDE_SKILL_DIR}/transcript.ts ${CLAUDE_SESSION_ID} [<uuid>]
```

出力が長ければファイルに書いてから分けて読む。`~/projects/h5notebook` が無ければ作らずにユーザーに伝えて止まる。

## 0. 続きか初回かを決める

`~/projects/h5notebook/textbooks/*/.checkpoint` のうち `sessionId` が `${CLAUDE_SESSION_ID}` のものを探す。

- ある → 「続き」。そのトピックが書き込み先。A へ。
- 無い → 「初回」。B へ。

## A. 続き（2回目以降）

1. `transcript.ts` に checkpoint の `uuid` を渡し、差分だけを読む。学んだ内容が無ければ「追加なし」と1行で書いて止まる（checkpoint は更新しない）。
2. 差分の内容を、既存の章に書き足すか新しい章にするかを決めて書き込む。新しい章の番号は既存の最大の `NN` の続き。README の目次も更新する。前の章の内容を差分で訂正した場合は、その章を訂正後の内容に直す。
3. `.checkpoint` の `uuid` を、1 の出力の最後の行の値に更新する。
4. 変更したファイルの絶対パスと、それぞれ何を足したかを1行ずつ出す。

## B. 初回

1. `transcript.ts` を uuid なしで実行し、セッションの最初から読む。そこで学んだ内容を拾い、次を提案する。まだファイルは作らない。
   - トピック（タイトル）の候補を2〜3個。それぞれ1行の説明つき。推奨を1つ示す。
   - 章立て（1章 = 1ファイル）。各章に1行の要約。
2. 過去のトピックと照らし合わせる。`textbooks/` が無い・空なら「重複なし」。`~/projects/h5notebook/textbooks/*/README.md` のタイトルと目次を読み、重複する章・内容があれば「どのトピックのどの章と重なるか」を具体的に指摘する。新しく作るか、既存のトピックに章を足すかを選んでもらう。重複が無ければ「重複なし」と1行で書く。
3. ユーザーに確認する（トピック・章立て・重複の扱い）。OK が出るまでファイルを作らない。修正があれば 1 からやり直す。
4. OK が出たら `~/projects/h5notebook/textbooks/<トピック>/` を作り、次を書く。`<トピック>` はタイトルをそのまま使う（日本語可。例：`プロセス間通信入門`）。既存トピックに足す場合は、そのディレクトリに章ファイルを足し、番号は既存の最大の `NN` の続きにして、README の目次を更新する。
   - `README.md`：`# <トピック>`、`目的：<1〜2行>`、目次（各章へのリンクと1行要約）、前提（OS など）。
   - `NN-<kebab-case>.md`：章ごとに1ファイル。会話で出た説明・例・コード・表を、教科書として読める文章に直す。会話で訂正した内容は訂正後の内容で書く。章同士は相対リンクで参照する。
   - `.checkpoint`：`{"sessionId": "${CLAUDE_SESSION_ID}", "uuid": "<1 の出力の最後の行の値>"}`。
5. 作ったファイルのリンクを出す。ローカルの絶対パス（README と各章）を一覧で示し、ユーザーがそのまま開いて確認できるようにする。

どちらの場合もコミットはしない（するならユーザーに聞く）。
